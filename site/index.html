Try it試用

macOS / Linux — build from source via Homebrew (no unsigned binary, nothing to trust blindly): macOS / Linux — 用 Homebrew 從原始碼編譯(沒有未簽章執行檔,不用盲目信任): 

# installs + builds the open-source renderer & updater安裝並從原始碼編譯開源 renderer 與 updater
brew install howieyoung/tap/cli-times

Start the ~6-hourly updater (one pull-only HTTPS request each time) so the brief stays fresh: 啟動每約 6 小時更新一次的 updater(每次只做一個「只拉取」的 HTTPS 請求),讓日報保持最新: 

brew services start cli-times

Then add this to ~/.claude/settings.json and reopen Claude Code: 接著把這段加進 ~/.claude/settings.json,重開 Claude Code: 

  "statusLine": { "type": "command", "command": "cli-times", "refreshInterval": 1 }

See the full brief any time (source links are clickable in modern terminals): 隨時看完整日報(連結在現代終端機可直接點): 

cli-times today

If the status line is blank, the signed feed hasn't landed yet — run cli-times today to check, or wait for the updater's next run. 若狀態列空白,表示簽章日報還沒抓到——先跑 cli-times today 確認,或等 updater 下次更新即可。

Will it cost me anything?會花到我的錢或額度嗎?

No. The status line runs locally and does not consume API tokens; the renderer has zero network code — it reads one local file and prints one line. It never touches your Claude or Codex account, and never reads your code, prompts, or files. A separate updater makes one pull-only HTTPS request every ~6h to fetch the day's signed brief; the CDN sees your IP like any download, we receive only aggregate counts, and it sends no identifiers, cookies, or content back. 不會。狀態列在本機執行、不消耗 API token;renderer 沒有任何網路程式碼——只讀一個本機檔案、印一行字,永遠不碰你的 Claude / Codex 帳號,也不讀你的程式碼、prompt 或檔案。另有一支獨立的 updater 每約 6 小時做一次「只拉取」的 HTTPS 請求抓當日的簽章日報;CDN 會像任何下載一樣看到你的 IP,我們只收到聚合數字,不送任何識別碼、cookie 或內容。
